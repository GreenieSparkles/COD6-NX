## 阶段清单（每项都要真机验收才算完成）

### 阶段 2：着色器 + 管线缓存
- [ ] 从 `native_renderer.cpp` 搬 `EnsureTranslated / TranslationThread / TakeCachedTranslation`
- [ ] 搬 `GetPipeline / CreatePipeline / PipelineThread / PrewarmPipelines`
- [ ] 搬 `InitializeSpirvCache`（SPIR-V 落盘缓存）
- 验收：native 模式下**能加载一个游戏真着色器**并建出管线（日志证明），画面仍由模拟层画

### 阶段 3：绘制（先 UI 小 quad）
- [ ] 搬 `BuildDrawSetup / Draw`（先只处理 `index_count ≤ 32` 且非程序化的绘制）
- [ ] 搬 `UpdateSystemConstants`（系统常量）
- 验收：用一个绘制做**逐像素截图对比**，与模拟层结果一致

### 阶段 4：渲染目标 + resolve
- [ ] 搬 `GetRenderTarget / CanonicalTargetKey / FindClearAlias / BeginPass`
- [ ] 搬 `Resolve / ResolveDownsampled / FlushResolveBarrier`
- 验收：菜单 fps 上升（目标 ≥ 20），画面无缺块

### 阶段 5：程序化全屏绘制（`A4A9`，64 次/帧）
- [ ] 搬 `native_geometry_shaders.cpp` 的 quad 展开
- 验收：程序化 UI 也由我们画，fps 继续上升

### 阶段 6：驱动层 + 其余优化
- [ ] `native_nvk_draw.cpp`（需要打了补丁的 mesa-switch）
- [ ] 批量记录、绑定键备忘、描述符池寿命、ZCULL
- 验收：菜单 30~40 fps

## 移植规则（血泪总结）

1. **先在确定会执行的地方打标记**，确认改动生效，再往下做（前面三次"改了没执行"的教训）；
2. 每阶段只搬一个模块，搬完立刻真机跑；
3. 默认 `xenos` 路径**永不修改**；
4. 一旦出现黑屏/卡死，回退到上一版并记录原因；
5. 验收靠日志数字（包数、管线数、绘制数、fps），不靠"看起来差不多"。

## 已知前置依赖（我们 SDK 里没有，需要补）

| COD5 用到 | 我们的状态 | 用途 |
|---|---|---|
| `RexGmSetReadOnlyMapped()` | ❌ 没有 | 关掉只读页监控（他们菜单 8→14 fps 的关键） |
| `nvk_switch_draw` / `set4`（mesa-switch 补丁） | ❌ 没有 | 绘制下沉到驱动，省 CPU |
| 他们的 `SharedMemory` 变体 | ❌ 没有 | 纹理/常量同步 |

**这三项要在阶段 5/6 之前补齐，否则那两步会卡住。**
