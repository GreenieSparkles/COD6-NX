## 二、结论：不是 GPU 慢，是 CPU 和 GPU 没有重叠

判读逻辑：

- 3 帧在飞（`kMaxFramesInFlight = 3`）、每帧 2 个提交 → 若 GPU 真是瓶颈，
  `BeginSubmission` 等到的应该是 **~6 个提交之前**，`retraso` ≈ 6。
- 实测 `retraso` = **1.66**：等的是**上一帧**的提交。
- 但每次真等 **28.5 ms**。
→ 也就是：GPU 干完上一帧要 ~28 ms，CPU 必须等它干完才能录下一帧 →
  **帧长 = CPU 35 ms + GPU 28 ms ≈ 64 ms**，而不是 max(35, 28) ≈ 35 ms。

## 三、为什么环只剩"一帧"

日志里这一行确认了机制：

    Skipping Vulkan frame presentation due to async placeholder draw usage in this frame

`async_shader_compilation = true` 时，用到占位管线的帧会被"关闭但不呈现"
（`skip_present_due_async_placeholder` 分支：`EndSubmission(true); return;`）。
但 `EndSubmission` 里仍然执行 `closed_frame_submissions_[(frame_current_++) % 3] = …`
——**这些没上屏的帧照样推进 3 帧的环**。于是等到的是刚关掉的那一帧，环退化成 1 帧。
