## 结果

140 号（版本 44）：日志里 **没有** `[cod6] PRIO: ...` 行，
`Cinematic` 仍然是 `prioridad 0x3B`、CPU 55.2%，fps 12.74。

## 四次尝试的经过

| 版本 | 位置 | 结果 |
|---|---|---|
| 40 | switch_perf.cpp 线程枚举处（按名字） | 无输出 |
| 41 | threading_switch.cpp 线程注册（按名字） | Horizon 拿不到线程名，代码空转 |
| 43 | switch_libc_supplement.c pthread_setname_np | 无输出 |
| 44 | switch_perf.cpp 算出 s.cpu 之后（按 CPU 占用） | 无输出 |

**共同点：代码都编译进去了（库 mtime 与源码一致），但日志一行都没有。**
说明执行的是另一份代码路径（SDK 里可能有多份线程报告/多个 perf 线程实现），
我改的位置都不在真正跑的那一份上。

## 决定

**放弃"降 Cinematic 优先级"这条路。** 四次都不成立，继续试是浪费运行次数。

**根治方案是参考项目的做法：用 FFmpeg 替换反编译的视频解码器**
（nfsmw_video_wmv3.cpp 416 行 + nfsmw_video_nativo.cpp 802 行 + bridge 125 行 = 1,343 行）。
那是唯一能把这块 CPU 真正砍掉的方法，但要 1~2 周。
