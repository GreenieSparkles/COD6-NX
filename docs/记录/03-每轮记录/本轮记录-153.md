## 一、先回答"19.59 是不是波动"

**是假的。** 它是最后一个报告窗口，紧跟在一次 **9.1 秒卡顿**后面：

    fotogramas=995  nuevos=59  fps=0.11   dt_medio=9104.0 ms
    fotogramas=1093 nuevos=98  fps=19.59  dt_medio=51.1  ms   ← 冻结后的短窗口

那个窗口只有 ~5 秒（不是 10 秒），又被冻结后涌出来的帧灌满，所以算出来 19.59。**不能当成绩。**

## 二、真正的稳态（剔除启动窗口和冻结窗口，取中位数）

| 号 | 版本 | 报告数 | 中位 fps | 中位 dt |
|---|---|---|---|---|
| 147 | 53 | 3 | 14.92 | 67.0 ms |
| 148 | 53 | 5 | 12.59 | 79.4 ms |
| 149 | 54 | 5 | 13.18 | 75.9 ms |
| 150 | 57 | 7 | 11.77 | 84.9 ms |
| **151** | **58** | **14** | **14.00** | **71.4 ms** |

    151 号的 14 个报告：12.58 / 13.16 / 13.90 / 13.93 / 13.94 / 13.96 / 14.00 / 14.01 / 14.03 /
                        14.03 / 14.07 / 14.09 / 15.70 / (19.59 假)

对比上一版（150 号，行为与 149 相同）11.77 → **+19%**；对比 149 的 13.18 → **+6%**。
而**同一个行为**不同两次运行就能差 12%（149 的 13.18 vs 150 的 11.77）。
→ 帧率上的收益**方向明确但幅度在噪声带附近**，不能说"涨了 50%"。

## 三、但机制层面是硬证据（不受波动影响）

    media_cola（读回那一段）      0.43 ms/绘制  →  0.00 ms/绘制（最高 0.01）
    带 memexport 的慢绘制          350 次 / 41.0 秒  →  16 次 / 0.13 秒
    inval_todo                     0            →  0

→ `readback_memexport = false` **确实把 GPU→CPU 同步去掉了**。

## 四、为什么省了 35% 的等待只涨 6%

因为那段是**等 GPU**：等的时候 GPU 在干活，工作量没变；去掉等待，瓶颈就移到别处
（现在帧长 71.4 ms，而"跳过全部绘制"能跑 61.7 fps，说明 GPU 侧一旦有活就顶住）。

## 五、这次日志把下一块肉定位出来了（重要）

剩下的慢绘制：**1,125 次（≥2 ms），合计 37.5 秒**，而且

    vfetch / barreras / draw / inval / cola 全部 = 0     ← 时间在"发出绘制之前"

再看 FASES / PREP3（每个窗口 120 次绘制）：

    PREP3 vert    = 51.6 ms（中位 42.0，最高 142.6）   ← 96% 的 prep 在这里
    PREP3 tex     =  0.43 ms
    PREP3 shader  =  0.00 ms
    rt_pipe       =  1.83 ms

`vert` 这一段 = 从 IssueDraw 入口到 `primitive_processor_->Process()` 结束，
**就是读客机顶点/索引数据的地方**（页监视是"取消映射"，每读一次就一次异常）。
合计 37.4 秒 ≈ 整轮墙上时间的 **48%**。
