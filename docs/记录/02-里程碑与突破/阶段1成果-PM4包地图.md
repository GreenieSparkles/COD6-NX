## 一、包分布（按次数）

| 类型 | opcode | 次数 | dwords | 含义 |
|---|---|---|---|---|
| **type-0** | — | **325,723** | **3,211,322** | **寄存器批量写**（状态负载） |
| type-2 | — | 100,863 | 100,863 | NOP（填充） |
| type-3 | **0x36** | **49,160** | 98,320 | `DRAW_INDX_2`（绘制） |
| type-3 | **0x27** | **25,338** | 76,014 | `IM_LOAD`（**切着色器**） |
| type-3 | **0x22** | **23,881** | 118,443 | `DRAW_INDX`（绘制） |
| type-3 | 0x3F | 10,339 | 31,017 | `EVENT_WRITE`（同步/中断） |
| type-3 | 0x3C | 8,555 | 51,330 | `WAIT_REG_MEM`（**等 GPU**） |
| type-3 | 0x2B | 7,582 | 148,587 | `IM_LOAD_IMMEDIATE`（内联着色器） |
| type-3 | 0x3B | 6,774 | 13,548 | 状态/内存包 |
| type-3 | 0x58 | 4,520 | 18,080 | `SET_CONSTANT`（常量写） |
| 其它 | — | ~9,000 | — | swap(0x64)、surface sync 等 |

**按每帧折算（约 1,000 帧）**：

    type-0 寄存器写   ≈ 325 次/帧   ← 最频繁
    绘制(0x22+0x36)   ≈ 73 次/帧    ← 与我们测到的 74 绘制/帧完全吻合
    IM_LOAD(切着色器)  ≈ 25 次/帧   ← 每帧 25 次着色器切换！
    WAIT_REG_MEM      ≈ 8.5 次/帧   ← 游戏在等 GPU
    NOP               ≈ 100 次/帧   ← 环对齐填充

## 二、这张图直接告诉我们自己写 Reader 要优化什么

1. **寄存器批量写是最大的热点**（次数和 dwords 都第一，3.2M dwords ≈ 12.8 KB/帧）：
   自己写 Reader 时不能"每写一次就更新状态"，要做**脏标记 + 合并**（参考项目的做法）；
2. **每帧 25 次着色器切换**：管线/描述符缓存必须极快，否则每帧 25 次查找就要命；
   参考项目为此做了"管线缓存 + 预热 + 后台创建"（我们已从 COD5 源码看到同样设计）；
3. **绘制 73 次/帧、WAIT_REG_MEM 8.5 次/帧**：同步点不多，但每次等待都可能让 CPU 停住；
4. **NOP 100 次/帧**：环里有大量填充，解析要能跳过。

## 三、同时得到的另一个重要结论：**它是 GPU 受限**

192 号这一轮里，用户先没超频、后来超频，同一版本同场景：

| 时钟 | 帧率 |
|---|---|
| 默认（未超频） | **5.7 / 6.2 / 6.8 fps** |
| CPU 1326 / GPU 768 / 内存 1600 | **13.7 / 13.3 / 14.1 fps** |

**2.3 倍**。而 CPU 只从 1020→1326（1.3×），GPU 从 307→768（2.5×）——
所以这 2.3 倍主要来自 **GPU 时钟**，说明当前帧时间是 **GPU 受限**（约 67 ms/帧在 768 MHz 下）。

这与"177 号：跳过全部绘制 → 41~44 fps"是一致的：**GPU 和模拟层记账两边都是大头**。

## 四、对计划的修正

| 原判断 | 修正后 |
|---|---|
| "80% 成本是模拟层记账（CPU）" | 准确说是"**CPU 记账 + GPU 绘制**两者叠加"：跳过绘制省 2.9×，超频 GPU 省 2.3× |
| 优先做 CPU 侧（Reader） | **两边都要**：Reader 解决 CPU 记账，渲染目标/resolve 与着色器精简解决 GPU 侧 |

所以阶段顺序调整为：

1. **阶段 1b（下一步）**：把这份地图变成"每帧包数/状态写量"的实时统计（已有基础，加时间戳即可）；
2. **阶段 2**：照 COD5 的 `Reader` 写自有环读取（只读不画，先验证包数与 SDK 一致）；
3. **阶段 3**：接管绘制（先 UI 类，再 `A4A9` 程序化全屏）；
4. **阶段 4**：渲染目标 + resolve 不拷贝 + 着色器精简（GPU 侧，直接对应这 2.3 倍里的那部分）。
