## 一、结论

    第 163 轮：洋红矩形（vkCmdClearAttachments）出现在最终画面上
    第 166 轮：屏幕被我们自己管线 + 自己着色器画的三角形覆盖（用户："屏幕红了"）

也就是说，下面这条链**全部打通**了：

    我们的 C++ → 我们的 SPIR-V → 我们的 VkPipeline → 真机 GPU → 屏幕上的像素

## 二、关键突破（之前 20 多轮都在这里打转）

**落点必须是 presenter 的 swapchain render pass，不是 IssueSwap。**

    在 IssueSwap 里发 CmdVkDraw      → 没有活动渲染目标，命令被丢弃（帧率都不变）
    在 presenter 的 pass 里画        → 出像素

而且管线要**按那个 render pass 创建**（`ci.renderPass = paint_context_.swapchain_render_pass`），
不能用动态渲染的管线——格式 37（R8G8B8A8）也要对上。

三个具体的坑，都记在代码注释里：

| 坑 | 现象 | 解法 |
|---|---|---|
| swapchain 格式 37，却按 44 建管线 | 静默丢绘制，无错误 | 按 `paint_context_.swapchain_render_pass_format` |
| 用动态渲染管线（renderPass=NULL） | 同上 | 按真实 render pass 建 |
| 在 IssueSwap 里画 | 无渲染目标，命令无效 | 在 presenter 的 final effect 之后画 |

## 四、下一步：把"测试三角形"换成"真实 UI 四边形"

已经确认可行的技术路线：

1. **CPU 侧采集**：在 `IssueDraw` 里把 `index_count <= 8` 的绘制连同顶点数据抓下来
   （索引 + fetch 常量 + `memory_->TranslatePhysical(addr<<2 & 0x1FFFFFFF)`，这个读法在
   `cod6_nativo.cpp` 的注释里已经写明，是参考项目验证过的）；
2. **上传**：每帧把这些四边形的位置塞进一个 host-visible 顶点缓冲；
3. **绘制**：在 presenter 的 final effect 之后，用我们的管线把四边形画出来（先不打纹理，
   画成纯色块）；
4. **验收**：屏幕上出现**位置和形状正确**的色块（和游戏 UI 的位置对得上）。

第 4 步一旦对上，就说明"顶点解码 + 坐标变换"这一整条数据通路是对的，
接下来才是纹理（字形、图标）和混合模式。

## 五、需要的工具

着色器用 `spirv-as`（本机已有）手工汇编，和现有调试着色器同一套流程
（源文件在 `tools/cod6_debug.*.spvasm`），不需要 glslang。
新增一个"顶点位置从 push constant 进来"的顶点着色器即可（6 个顶点 × vec2 = 48 字节，
远小于 128 字节的 push constant 下限）。
