# 阶段一：平台层（第 1–50 次，10-23 → 10-29）

## 第 1 次 · 10-23 18:00 · 最早的那次实验

- 日志：`NSLITE\新建文件夹\logs\rex`，4 行
- **突破**：`[apm]` 调频成功、**NVK 起来了**（第一次确认 Switch 上 Vulkan 可用）
- **卡点**：`std::terminate: std::bad_alloc` —— 堆没配够

## 第 2–3 次 · 10-28 09:44 / 09:46 · 启动即崩

- 只有 4–5 行 saltynx，程序立刻死

## 第 4–7 次 · 10-28 12:12 → 12:32 · **spdlog 死锁**

- 分别卡在 `ctx: calling logger->log` → `ctx: about to REXLOG_INFO`
- **突破**：加细标记定位到 spdlog 初始化（FILE 锁）
- 第 8 次修法：换裸 `write(2)` → **绕过成功，走到 phase 2/9**

## 第 10–19 次 · 10-28 12:55 → 18:11 · **缺 cod6.toml（10 次白跑）**

- 现象：`Too few processor cores`
- **突破**：发现 `gpu_plugin` 默认空串 → **根本没加载图形插件**
- 第 20 次（18:13）补上 `cod6.toml` → 日志暴涨到 166 行，**GPU 终于起来了**

## 第 13–18 次 · 10-28 13:16 → 14:08 · 线程创建卡死

- `pthread_setcanceltype(ASYNCHRONOUS)` + `assert_always()` 杀掉每个新线程
- 改 `PTHREAD_CANCEL_DEFERRED`

## 第 21–33 次 · 10-28 18:30 → 21:39 · **newlib 互斥量不唤醒 + ABBA 死锁**

- `state_mutex_` 争用不唤醒 → `WaitStarted()` 卡住
- `heap_mutex_` 争用不唤醒 → `SystemHeapAlloc` 阻塞
- 第 24 次：`Guest memory arena mapped` —— **客户机内存预留成功**
- 第 32 次：`global_critical_region` 与 `heap_mutex_` 的 **ABBA 死锁**

## 第 35–38 次 · 10-28 22:26 → 22:59 · **发现异常槽位被泄漏**

- 首次出现大量缺页记录（`[eh]` = 33）
- **两次硬约束确认**：`svcSetProcessMemoryPermission` 返回 **0xD401**（页权限改不了）
- **一次缺页吃两个槽位**

## ★ 第 39 次 · 10-28 23:08 · **第一次加载客户机镜像成功**

```
phase 3/9: loading guest image
  XEX image loaded successfully
phase 6/9: launching guest thread
[xt] Create: entry 0x82370938
```

- 修法：`RexGmMapCommittedNow()` —— 提交时就映射
- **日志从 614 行暴涨到 1556 行**
- 代价：这个做法后来被官方文档否定（见第 50 次后），已删除

## 第 43–46 次 · 10-29 00:05 → 00:29 · 红黑树被破坏

- `far=0x68`，换参考版 threading 无效
- **突破**：全部自旋锁换标准锁也无效 → **说明不是锁**

## ★ 第 47 次 · 10-29 00:44 · **第一次拿到真实崩溃信息（最关键的一次）**

```
pc   imagen+0xc1514
instruccion 0xf9000073  =  str x19, [x3]
far 0x48
x3  0x48
```

- **根因**：缺页交给 SEH，SEH 说「我处理了」，线程被放回原指令重试 → 再缺页 → 占下一个槽位 → 24 个槽位耗尽后 **既不崩也不前进**
- **修法**：只有落在客户机窗口内的缺页才交给 SEH；宿主地址缺页直接打崩溃日志并退出
- **意义：把"静默死锁"变成"带调用栈的崩溃"。没有这一步，后面三轮不可能有进展。**

## ★ 第 50 次 · 10-29 01:53 · **游戏真正跑起来了**

```
Presenter: modo de pintado -> desde el hilo del juego
AudioSystem::RegisterClient: client index=0 queued_frames=8
Resolve: 0,0 <= x,y < 1280,720, k_8_8_8_8 at 0x1DF1E000
[rex] XELOG_GPU PRESENT: swap_texture_view=0x...
phase 7/9: guest thread running
```

- **根因**：编译时缺 `-mtp=soft` → `mrs tpidr_el0` 永远是 0（Horizon 不用该寄存器）
- **修法**：`switch-devkitA64.cmake` 加 `-mtp=soft`
- **第一次：客户机执行真实游戏代码、向 GPU 下命令、提交画面、播放音频**
- 剩余问题：只提交 1 帧（0.0 fps），然后自己 `TerminateTitle`

## 第 50 次之后查出的两个问题

| 问题 | 根因 | 状态 |
|---|---|---|
| `NtSuspendThread` 全部失败 | `RexSwitchRegisterCurrentThread()` **零个调用点**，注册表永远是空的 | 已修 |
| 关闭时崩溃 | `std::thread::detach()` 在 Horizon 上抛 `std::system_error` | 不影响画面，记录在案 |

## 前 50 次的结论：真正的根因只有六个

1. spdlog 在 Switch 上卡死 → 裸 `write(2)`
2. 缺 `cod6.toml` → 没有图形插件（10 次白跑）
3. newlib 互斥量争用不唤醒 → 线程创建/堆分配阻塞
4. libnx 异常槽位被泄漏 → 一次缺页吃两个槽位
5. 与官方文档相反的做法（"提交即映射"）→ 加了又删
6. **缺 `-mtp=soft` → 所有 TLS 崩溃（最久，第 43–50 次）**
