**现象**：日志从 614 行暴涨到 1556 行

```
phase 3/9: loading guest image
Loading XEX image: game:\default.xex
  XEX image loaded successfully
phase 4/9 / phase 5/9 / OnInitialize returned true
phase 6/9: launching guest thread
[xt] Create: entry 0x82370938
```

**原因**：前 38 次一直卡在客户机内存的惰性映射：每次首次访问一个页都触发缺页异常，而 libnx 全程序只有一套异常栈，多线程同时缺页就耗尽。

**修法**：加 `RexGmMapCommittedNow()`，提交内存时就映射进视图。

**代价**：这个做法后来被官方文档否定（见第 50 次），已删除。

---

### ★ 第 47 次（10-29 00:44）—— 第一次拿到真实崩溃信息

**现象**：`[eh]` 从 24 次降到 **1 次**，并生成第一条有意义的 `rex_crash.log`：

```
pc   imagen+0xc1514
instruccion 0xf9000073  =  str x19, [x3]
far 0x48
x3  0x48
```

**原因**：遇到不可修复的缺页时，处理器交给 SEH，SEH 说「我处理了」，线程被放回原指令重试 → 再缺页 → 占下一个槽位。24 个槽位耗尽后异常入口无限空转 —— **既不崩溃也不前进**。

**修法**：只有落在客户机窗口内的缺页才交给 SEH；宿主地址的缺页直接打崩溃日志并退出。

**意义**：把「静默死锁」变成「带调用栈的崩溃」。没有这一步，后面三轮不可能有进展。

---

### ★ 第 50 次（10-29 01:53）—— 游戏真正跑起来了

**现象**：`TLS` 相关日志 0 条（TLS 崩溃消失），出现

```
Presenter: modo de pintado -> desde el hilo del juego, presentando en el acto
AudioSystem::RegisterClient: client index=0 queued_frames=8
Resolve: 0,0 <= x,y < 1280,720, k_8_8_8_8 at 0x1DF1E000
[rex] XELOG_GPU PRESENT: swap_texture_view=0x...
XAudioSubmitRenderDriverFrame × 8 次，连续
XGIUserSetContextEx × 3
XamNotifyCreateListener
phase 7/9: guest thread running
```

**第一次：客户机在执行真实游戏代码、向 GPU 下命令、提交画面、播放音频。**

**原因**：前面所有 TLS 崩溃（`ThreadStartRoutine` 崩、主线程崩、`IsInThread` 崩、`far=0x48` / `far=0xA0`）都是同一个根因 —— 编译时缺 `-mtp=soft`。

nfsmw-nx `docs/toolchain.md` 原文：

> "One part of GCC's recording code reads a per-thread value with `mrs tpidr_el0`, which is **always 0 on Horizon** because libnx does not use it (`-mtp=soft`)."

```
我们：  -march=armv8-a+crc+crypto -mtune=cortex-a57 -ftls-model=local-exec -fPIE
参考：  -march=armv8-a+crc+crypto -mtune=cortex-a57 -mtp=soft -ftls-model=local-exec -fPIE
```

**修法**：`tools/switch/cmake/switch-devkitA64.cmake` 第 61 行加 `-mtp=soft`。

**验证**：

```asm
之前： mrs  x1, tpidr_el0        ← 永远是 0，一读就崩
之后： bl   __aarch64_read_tp     ← 真正的线程指针
```

**剩下的问题**：只提交 1 帧（`XELOG_GPU PRESENT` 1 次，`juego 0.0 fps`），然后游戏自己 `TerminateTitle` 退出。

- 第 50 次之后：`std::terminate: std::system_error`（`std::thread::detach()` 在 Horizon 上抛异常）

## 第 50 次之后查出的两个问题

### 1. `NtSuspendThread` 全部失败（已修）

```
[NtSuspendThread] -> 0xc0000001 suspend_count=1   ×4
```

**原因**：`RexSwitchRegisterCurrentThread()` 在 SDK 里**只有声明和定义，零个调用点**，所以「pthread → 内核句柄」注册表永远是空的，对任何别的线程都返回无效句柄，`Suspend`/`Resume`/亲和性全部 `ESRCH` 失败。

**修法**：线程入口注册自己，主线程启动时也注册。

### 2. 关闭时崩溃（不影响画面）

```
#05 MnkInputDriver::DetachFromWindow()   ← 析构里抛 std::system_error
#08 InputSystem::Shutdown()
#11 ReXApp::OnDestroy()
```

官方文档明写了：`std::thread::detach()` 在 Horizon 上会抛 `std::system_error` → `std::terminate` → 游戏关闭。

## 结论：50 次里真正的根因只有六个

1. **spdlog 在 Switch 上卡死**（第 4–7 次）→ 换成裸 `write(2)` 日志
2. **缺 `cod6.toml`** → 没有图形插件（第 10–19 次，共 10 次运行）
3. **newlib 互斥量争用不唤醒** → 线程创建 / 堆分配阻塞（第 21–33 次）
4. **libnx 异常槽位被泄漏** → 一次缺页吃两个槽位（第 35–42 次）
5. **与官方文档相反的做法** →「提交即映射」我加了又删（第 39 次加、第 50 次后删）
6. **缺 `-mtp=soft`** → 所有 TLS 崩溃（第 43–50 次，最久）

**前 46 次进展慢，是因为没有崩溃信息、只能猜锁。第 47 次把死锁变成崩溃之后，三次运行就走到游戏运行。**
