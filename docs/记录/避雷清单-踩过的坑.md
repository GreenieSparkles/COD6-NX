# 避雷清单 —— 这个项目踩过的所有坑

写于 2026-10-31。**动手前先扫一遍，能省掉一到两天的白工。**
每一条都是实测踩出来的，不是推测。

---

## 一、构建与工具链

| 坑 | 症状 | 怎么避 |
|---|---|---|
| **缺 `-mtp=soft`** | `mrs tpidr_el0` 读到 0 → 所有线程 TLS 崩溃，`far=0x48`/`0xA0` | Switch 交叉编译必须加 `-mtp=soft`（Horizon 不用该寄存器） |
| **中文路径** | `rexglue codegen` 静默失败、`generated/` 为空；PowerShell 写 toml 变乱码 | **工具链一律走纯 ASCII 路径**。本工程用 junction：`D:\cod6data` → 实际数据 |
| **toml 带 BOM** | TOML 解析失败，配置全不生效，表现为"改了没反应" | 写 toml 必须 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`；写完用 `tomllib` 验一遍 |
| **cvar 用 `kInitOnly`** | toml 里写 `true`，运行时读到 `false`，整轮白跑（121 号） | 调试开关一律 `kHotReload`（`kAnyChange` 不存在，编译期会报） |
| **`rexglue init` 坏了** | 只打印 banner，不生成 `CMakeLists.txt`，无报错 | 手写 `CMakeLists.txt`：`include(generated/rexglue.cmake)` + `include(generated/default/sources.cmake)` |
| **`rexglue_apply_recomp_settings` 未定义** | CMake 报 "invoked with incorrect arguments"，SDK 里根本没有这个函数 | 直接删掉这个调用 |
| **`.git` 丢了** | `git submodule update` 报 "not a git repository"，SDL3 拉不下来 | 子模块只能手动放；或用系统里已装的 SDK（WSL 的 `/opt/rexglue-linux`） |
| **manifest 路径要匹配工具平台** | Windows 的 rexglue 要 `D:/...`，WSL 的 rexglue 要 `/mnt/d/...`，混用报 "Entrypoint XEX not found" | 编哪边就写哪边的路径 |
| **debug/release 混用** | 日志里 `[rex]` 行数忽然暴涨/暴跌，误判成性能变化 | 每次出包记 `md5`，用 `resumen.txt` 第一行的版本号确认"跑的是哪一版" |

## 二、Switch 平台（Horizon）硬约束

| 坑 | 症状 | 怎么避 |
|---|---|---|
| **`svcSetProcessMemoryPermission` 返回 `0xD401`** | 页权限改不了 → SDK 只能"取消映射"代替只读监视 → **每读被监视页 4 字节就是一次 CPU 异常** | 这是硬约束。**不要试图在这里做纹理热更新**；走自写渲染器直接读 guest 内存 |
| **`std::thread` / `std::thread::detach()`** | `std::terminate: std::system_error` → 黑屏（73–75 号） | **不要用 `std::thread`**；用 libnx 线程或 SDK 的线程封装 |
| **spdlog 初始化卡死** | 停在 `ctx: calling logger->log`，无崩溃 | 日志走裸 `write(2)`，不要依赖 spdlog 的 FILE 锁 |
| **newlib 互斥量争用不唤醒** | 线程创建/堆分配莫名阻塞，ABBA 死锁 | 平台层互斥量换实现；不要假设 pthread 语义完整 |
| **异常槽位泄漏** | 一次缺页吃两个槽位，耗尽后**既不崩也不前进** | 只把"guest 窗口内"的缺页交给 SEH；宿主地址缺页直接打崩溃日志退出 |
| **`protect_zero = true`** | 任务加载崩溃：`sub_821254B0` 读 `[NULL+44]`（合法行为） | **必须 `protect_zero = false`** |
| **地址空间耗尽** | `AllocFixed: no pudo confirmar ... 0x40000` + `[xt] Create: entry 0x00000000` | 冷启动再跑；连续多轮测试后会碎片化 |
| **`log_level` 曾是假开关** | Switch 分支忽略 `(void)(cat); (void)(lvl);`，trace/debug 全量写 SD 卡 | 已修成编译期删除。**任何"性能开关"都要验证真的生效** |

## 三、SD 卡（我犯过的最严重错误）

| 坑 | 后果 | 怎么避 |
|---|---|---|
| **多线程并发写同一个文件** | 管线缓存从多个工作线程 `fopen/fwrite` → **FAT 表被写坏**：`cache\shaders` 里 65 个垃圾文件、`game_root`/`logs`/`user` 变"损坏且无法读取"、普通删除无效（文件名含非法字符） | **绝对不要并发写卡**。缓存只在 `Shutdown` 单线程写一次并加互斥锁；最好干脆只读不写 |
| 写卡频率高 | FAT 更容易坏 | 日志走 `append`；不做周期性落盘 |

**修复办法**：管理员 `chkdsk F: /f`，或格式化后从 `完整部署包`（含 `game_root` 6.8 GB）重拷。

## 四、图形 / Vulkan

| 坑 | 症状 | 怎么避 |
|---|---|---|
| **小绘制是"1 顶点、无索引缓冲"** | `vkCmdDraw(1,1,0,0)` + TRIANGLE_LIST = **0 个三角形**，永远画不出东西 | 游戏靠顶点着色器把 1 个顶点展开成方块。**自写着色器必须自己生成几何**（如用 `gl_VertexIndex` 造全屏三角形） |
| **SDK 用动态渲染** | `current_render_pass_ == VK_NULL_HANDLE`，按老写法建管线永远失败 | 用 `VkPipelineRenderingCreateInfo` 声明颜色/深度格式，`renderPass = VK_NULL_HANDLE` |
| **不声明深度附件** | 管线建成功（VkResult 全 0），**绘制被静默丢弃** | 声明 `depthAttachmentFormat`（本工程用 `D24_UNORM_S8_UINT`）+ 深度状态结构 |
| **scissor 被 SDK 设成小矩形** | 全屏三角形被裁没 | 画之前自己 `CmdVkSetViewport` + `CmdVkSetScissor` 满屏 |
| **画在帧中间** | 像素被后续全屏绘制盖掉 | 想"看得见"就画在帧末（`IssueSwap` 之前） |
| **管线创建代码放错位置** | 日志一行都没有，误以为 cvar 没生效 | 放在 `IssueDraw` **开头**（每帧必执行）；放在"小绘制分支前"实测不执行 |
| **Vulkan 静默失败** | 画不出来但零日志、零崩溃 | 别靠肉眼！用 `media_dibujo` 对比（涂满屏会让单次绘制耗时从 0.45→1.1 ms）或 pipeline statistics |

## 五、测试方法与数据判读（我多次误判的地方）

| 坑 | 后果 | 怎么避 |
|---|---|---|
| **文件夹编号 ≠ 轮次编号** | `(50)` 有两个、`(0)` 有三个，中间跳号 | 只认**时间戳**和 `resumen.txt` 里的 `version=` |
| **同一次运行被复制多份** | 78–85 全是 `fps=4.23 / 854 帧`，被当成 8 次数据 | 看 `fotogramas` 和 `dt_medio` 是否完全相同 |
| **只看一个日志文件就下结论** | 我只看 6 KB 的截断日志 → 误判"启动就死"（123 号），被用户当场纠正 | **一次扫全部 `*.log`，并且大小写都搜**（`NATIVO` / `nativo`） |
| **超频前后比帧率** | 12 fps vs 5 fps 被误判成"native 模式慢一倍" | 记下是否超频。超频差约 1.4 倍 |
| **只测菜单就当结论** | 菜单 18.69 fps 被说成"可用"，关卡内其实 0.5 fps | 必须报 `dibujos_por_fotograma`：≈**70** 是菜单，≈**5000** 是关卡内，**0** 是跳过绘制 |
| **跳过绘制测出 60 fps 就以为渲染器能救一切** | 菜单确实如此；**关卡内跳过绘制只有 13.7 fps**（128 号） | 天花板由游戏自身 CPU 决定，渲染器只能逼近它 |

## 六、流程

| 坑 | 怎么避 |
|---|---|
| 让用户自己去一堆文件夹里找文件 | **每轮把要拷的东西放进 `测试\【一次复制】直接拷到卡根目录\switch\`**，只让他拖一个文件夹 |
| 一次改多处，出问题分不清 | **一次只改一件事，改完立刻编译、立刻出包** |
| 用字符串锚点打补丁（反复失败） | 文件改多了锚点就对不上。**改用行号 + 唯一上下文插入**，并立刻 `grep` 验证 |
| 上下文丢失后无法接手 | 每轮写 `本轮记录-*.md` 并复制进 `备份\`，另维护 `接续指南-给下一个会话.md` |
| 假设 PC 版能跑 | 用户明确说过：**PC 版从来没跑起来过（一直黑屏）**，不要拿它当既成事实 |

## 七、一句话总结

**这个项目里真正花时间的不是写功能，是下面三类：**

1. **平台的沉默失败**（spdlog、0xD401、Vulkan 丢绘制）—— 只能靠"让它崩溃"和"量出数字"来定位
2. **路径/编码/开关这类小坑**（中文路径、BOM、kInitOnly）—— 每次都能吞掉一整轮
3. **我自己的误判**（读错日志、只读一个文件、把菜单当成关卡）—— 靠固定流程和交叉验证避免

## 网络日志：绝对不要在启动路径里调 nxlinkStdio()（第 157 轮，黑屏事故）

**现象**：加了"日志走网络"的版本推上去后，**主菜单全黑**。

**原因**：在 OnPostSetup（启动路径）里调用 
xlinkStdio()。它会在没有 host 时阻塞，
于是应用卡在启动阶段，一帧都没画。

**规矩**：

1. 启动路径里不许有任何可能阻塞的网络调用（
xlinkStdio、connect、ecv）。
2. 网络日志如果要加，必须是**开关文件启用、非阻塞 UDP、在 guest 跑起来之后**才初始化；
   没有开关文件时，代码路径必须和现在完全一样。
3. 每次这种"便利功能"出问题，代价是用户一次黑屏 + 一次重启。

**回退办法**：源码备份里有当时可用的 src/cod6_app.h（备份\完整备份-2026-10-31-62\03-修改过的源码\src\）。

## 推送（netloader）的两个注意点

- hbmenu 的 netloader **一次连接失败后就可能不再监听**，需要重新进 hbmenu；
  所以推送脚本要重试（实测第 13 次才成功，约 2 分钟）。
- 
xlink 的 -p cod6-nx/cod6.nro 会把文件放到 sdmc:/switch/cod6-nx/，
  和插卡路径一致，因此 game_root/logs 都不用改。

## netloader 启动必须用 title override（第 157 轮，连续两次黑屏的真凶）

**现象**：推送后游戏启动到 phase 7/9 就停在 ~6 秒，一帧都不画，黑屏。

**证据**（新建文件夹 157 的 rex_perfil.log 第一行）：

    失败那次： invitado 504/485 MB | proceso 3185/3189 MB
    成功那次： invitado 505/921 MB | proceso 3185/3189 MB   ← 155 号（卡上运行）

**原因**：hbmenu 从**相册**打开 = applet 模式，进程拿不到完整内存，
客机内存只映射到 485 MB（需要 921 MB），进程顶到 3189 MB 上限，游戏卡死。

**正确做法**：主菜单光标停在任意游戏图标上 → **按住 R** → 按 A → hbmenu 以
title override 打开（完整内存）→ 这时 netloader 推送出去才能正常跑。

**版本 63 起会自己报告**：

    [cod6] MODO applet=6 (aplicacion (memoria completa))  invitado=504/921 MB
    [cod6] MODO AVISO: lanzado como applet. ...   ← 出现这行就是开错了

以后任何黑屏，先看这一行，再怀疑代码。
