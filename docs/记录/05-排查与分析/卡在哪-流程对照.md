## 二、为什么不推进（四个真实原因，按影响排序）

### 1）迭代成本是"插一次卡"，不是"编译一次" —— 最根本的一条（正在解决）

PC 版本身是通的（见上表），但**那个 PC 构建只编译了 `src/main.cpp`（原版 ReXGlue 工程）**，
我们自己的代码（`cod6_nativo.cpp`、`cod6_renderizador.cpp`、我们改过的 SDK）从来没有在 PC 上跑过。
所以每验证一个猜测，成本是：

    构建 → 拷到卡 → 拔卡插卡 → 启动游戏 → 玩/停 → 退出 → 取日志 → 分析

**一小时最多两三次实验。** 在这种成本下，"再测一个指标"永远比"改造结构"划算，
于是我们就一直在测。这不是判断失误，是成本结构决定的——但结果就是原地转圈。

**第 155 轮已开始解决**：用我们自己的源码树配置了 Linux PC 构建
（`/opt/switch/cod6-ng/out/pc`，clang-18 + 我们改过的 SDK + 完整 SDL3 3.4.18），
一旦编过，渲染器开发就能在 PC 上做：Xvfb + lavapipe 跑，日志和截图都是本地的。

### 2）我们把力气花在模拟层上，因为它能立刻测出"真 bug"

修掉的都是真问题：`log_level` 假开关（8.60 → 12.43 fps）、`0xD401` 页监视、memexport 读回（每次 94 ms）、
共 15 种诊断。但参考项目明确写过：**不要优化模拟层，换掉它**。
所以这些都修完之后，架构没变——用回归把场景权重扣掉后，v53→v60 的 fps 是平的（残差 ±7%）。

### 3）渲染器撞上第一堵墙就绕开了

项目自己的《原生渲染器-实现计划》N3-1 写着：顶点格式不在 fetch constant 里、手读顶点崩过一次
（`Unhandled guest access violation: read of guest 0x80400002`）。
之后我们没有继续打穿它，而是转去做测量。
参考项目的做法是：顶点解码照它自己的 `nfsmw_nativo_dibujos.cpp`（属性布局/stride/offset），
并把"读到正确顶点"当成必须过的验收点，而不是可选项。

### 4）没有可比的 A/B 口径，改进不可见

直到第 155 轮我们才有"归一化 fps + 机制指标"。之前每次运行停在不同菜单画面
（53~86 绘制/帧），fps 13 和 15 无法区分是改动还是场景。**没有反馈信号，就无法判断该投入哪条路。**

## 三、要推进，必须先改这三件事

### A. 把迭代成本降下来（最高优先，其它都受它制约）

1. **网络部署（首选）**：本机有 `/opt/devkitpro/tools/bin/nxlink`。
   如果 Switch 与电脑同一 WiFi、用 hbmenu 的 netloader 启动，部署从"插卡一次"变成"几秒钟一次"。
   这是唯一能让"渲染器开发"这种需要几百次迭代的活变得可行的办法。
2. **备援：修 PC 版**（参考项目第 1 步）。WSL 里有 lavapipe 软件 Vulkan（`lvp_icd.json`），
   可以无 GPU 跑正确性验证；代价是没有 WSLg 图形窗口，只能离屏/截图验证。

### B. 冻结"模拟层微调"，把第 3 步当唯一主线

按参考项目的顺序推进渲染器，每个里程碑的验收是**屏幕上的像素**，不是 fps：

    ① 顶点/索引解码（照 nfsmw_nativo_dibujos.cpp）→ 日志里出现真实顶点值
    ② 自己的管线 + 绑定 → 画出覆盖在原画面上的方块，位置正确
    ③ 接管全部 UI 小绘制（index_count ≤ 8）→ 菜单 UI 由我们画
    ④ 纹理 untiling + 指纹缓存 → 真实贴图
    ⑤ 渲染目标替代 EDRAM / resolve 不拷贝 → 接管场景

### C. 同步做第 6 步里最便宜的两项（不碰渲染架构）

- **direct calls + LTO**（55,205 次弱别名调用 + 0 处 `-flto`）→ 游戏自身代码 +10~15%，
  直接影响关卡内的 73 ms 天花板。
- **把 `Cinematic` 等忙等换成真等待**（主菜单 46.3%、关卡内 76.8%）。

## 四、需要用户配合的一件事

**能不能用 hbmenu 的 netloader？** 如果能：

1. Switch 连上家里的 WiFi（和这台电脑同一个网段）；
2. 启动方式改为：按住 R 点任意游戏图标进 hbmenu（title override，保证完整内存）；
3. 告诉我 Switch 的 IP；

之后我每次构建完直接 `nxlink -a <IP> cod6.nro`，不用再插卡。迭代从"分钟级"变成"秒级"，
这样第 3 步的渲染器才有可能在合理时间内推进。

如果 netloader 不可用，我就先去把 PC 版修通（第 1 步），用它做渲染器的打磨环境。
