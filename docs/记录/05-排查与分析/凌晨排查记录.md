## 一、环境层修掉两个真 bug

| 问题 | 症状 | 修复 |
|---|---|---|
| **缺 `libasound.so.2`** | `SDL_InitSubSystem(SDL_INIT_AUDIO) failed`，紧接着就是 guest 0x3C 违例 | `apt install libasound2t64 libpulse0` ✅ |
| **`/dev/shm` 被残留 arena 占满** | 每次 `kill -9` 泄漏一个 4.8 GB `/dev/shm/xenia_memory_*`；满了以后 mmap 被截断 → **SIGBUS**，看起来像莫名崩溃 | `rm -f /dev/shm/xenia_memory_*`，已写进 `round.sh` ✅ |
| WSL1 无客户机内存映射 | 死循环 | 已升级 WSL2 ✅ |

这两条**污染过之前的多次实验**，现在测试脚本每次自动清理。

## 三、perf 无扰动采样 —— 最关键的一次观测

```
perf record -F 499 -p <pid>   →  15408 个采样
落在 cod6（重编译代码）内的：1 个
CPU 热点：llvmpipe 线程（/tmp/perf-*.map = LLVM JIT 着色器编译）+ 内核锁
```

**结论：CPU 几乎全花在 lavapipe（软件 Vulkan）JIT 编译着色器上，不是在跑游戏代码。**

那个 guest `0x3C` 空转，是**游戏在等 GPU 排空 ring，而软件渲染器卡在编译着色器**。

## 四、已用证据排除的假设

| 假设 | 证据 |
|---|---|
| 游戏文件损坏 | ISO 内 152 项逐个比对，151 一致 |
| 跳转表被截断 | 用从内存挖出的 PPC 镜像跑 `switch_check.py`：**truncated 0 / wrong targets 0 / missed 0** |
| 生成代码翻译错 | 逐条对照 `sub_820B9AE8` / `sub_820BA240` 的 PPC 与 C++：空指针检查、`rlwinm.` 的 CR0 更新**都正确** |
| 分配器返回 0 | 探针显示返回**有效指针** `0xBFB9C0xx`，`flag10941` bit5 = 0 |
| `VdGetSystemCommandBuffer` 返回假地址 | 反汇编确认 `0xBEEF0000/1` 是 **Xenia 故意为之** |
| gap 是漏翻译代码 | 180 个候选全在 code region 外（对齐填充） |
| 竞态 | 单核 `taskset -c 0` 仍稳定复现（48 万次 / 15 秒） |
| GPU 插件有问题 | **不加载插件行为完全一样** |
| 音频缺失导致 | 装好 ALSA 后音频错误消失，崩溃依旧 |
| `-fno-strict-aliasing` 能修 | 反而导致 SIGBUS |

## 五、重大工具突破：从内存挖出 PPC 镜像

ReXGlue 不提供 image dump，但**客户机镜像就在内存里**：

```
客人 0x82000000 → 宿主 0x182000000   （base 0x100000000 + VA，1:1）
dump 0x182000000 起 31 MB → /opt/dump/cod6_image.bin（以 "MZ" 开头）
```

有了它，`switch_check.py` / `find_gaps.py` / `pointer_audit.py` 这些前任工具**全部可用**。
