# 二、这一场（154~167 轮）真正的成果

## 1. 里程碑② 完成：我们自己的管线在真机上画出了像素

    163 号：洋红矩形出现在最终画面（vkCmdClearAttachments）
    166 号：整屏被我们管线 + 我们着色器画的三角形覆盖（用户："屏幕红了"）

链路全部打通：**我们的 C++ → 我们的 SPIR-V → 我们的 VkPipeline → 真机 GPU → 屏幕像素**

## 2. 找到了卡了 20 多轮的真正原因

| 坑 | 现象 | 正确答案 |
|---|---|---|
| 在 `IssueSwap` 里发 `CmdVkDraw` | 命令被丢弃，**连帧率都不变** | 必须在 **presenter 的 swapchain render pass** 里画 |
| 用动态渲染管线（renderPass=NULL） | 静默丢绘制，零错误 | 管线要按**真实 render pass** 建 |
| 按格式 44(B8G8R8A8) 建，实际是 37(R8G8B8A8) | 同上 | 用 `paint_context_.swapchain_render_pass_format` |

## 3. 排除了三个假设（都有数据）

- **帧环深度**：v62 把 3 改成 6，`ANILLO cierres/presentacion=1.00`，FENCE 阻塞消失
  → 但 fps 一动不动 → **等待是症状不是病因，主菜单是 GPU/呈现受限**。
- **跳过不完整帧**：v61 的 toml 改动无任何效果。
- **PC 版高帧数能代表 Switch**：不能。参考项目原话：PC 只告诉你"活在哪"，不告诉你"在 Switch 上多贵"。

## 4. 两个"连环事故"的根因（都不是代码坏了）

| 事故 | 真因 | 现在怎么防 |
|---|---|---|
| 156~159 连续黑屏 | **卡上的 cod6.toml 被写坏了**（`invalid utf-8`）→ 整份配置失效 → `gpu_plugin` 为空 → 不加载 GPU 插件 → 零帧 | v63 起：`gpu_plugin` 为空时程序自己用 `xenos`，并打印警告 |
| 164 黑屏 | **netloader 上传的 nro 和编译出来的不一致**（md5 对不上）→ 加载失败 | 结论：**nro 一律线缆复制**；netloader 只用于快速试且必须校验 |

## 5. 基础设施：现在我能自己闭环

- **推送**：`nxlink`（不可靠，需 md5 校验）或线缆（可靠）
- **读日志**：`http://192.168.31.160:1234/switch/cod6-nx/logs/`（真机开的 HTTP 服务器，只读）
