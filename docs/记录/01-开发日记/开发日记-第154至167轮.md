这一段的主题：**从"调模拟层参数"彻底转到"写自己的渲染器"**，并且真的画出了像素。

## 154 号 · toml 改动的判读（v61）

- `vulkan_async_skip_incomplete_frames = false` 生效了（`Skipping Vulkan frame` 出现 0 次）。
- 结果：13.22 fps、80.8 绘制/帧 → 归一化 13.34，**和上一版一模一样**。
- 教训：这个假设（跳帧导致串行化）被推翻，不再回来。

## 155 号 · 帧环 3→6（v62）

- 新增 `[perf] ANILLO`：`cierres/presentacion = 1.00`（23 行，0.98~1.00）
  → 环确实"一次呈现推进一格"，**"环被过度消耗"的猜测被推翻**。
- `[perf] FENCE` **一行都没有** → 阻塞等待几乎消失，CPU 侧的问题被修掉。
- 但 fps 13.93 → 归一化 13.33，**一动不动**。
- 结论（重要）：**等待是症状不是病因**。CPU 只用了 1 个核，主菜单受 GPU/呈现限制。

## 156~159 号 · 连续黑屏 → 找到真凶

现象都一样：`phase 7/9` 之后 ~6 秒停住，零帧，客机内存只映射 **485 MB**（正常 883~921 MB）。

排查过程（走了弯路，记下来）：

1. 先怀疑 hbmenu 的 applet 模式内存不够 → 加了 `[cod6] MODO applet=…` 自检
   → 实测 `applet=0`（= Application），**模式没问题，这个假设错**。
2. 再怀疑我自己加的 `nxlinkStdio()`（网络日志）→ 回退，仍然黑屏。
3. 最后在日志里看到决定性的一行：

       [rex] Failed to parse config /switch/cod6-nx/cod6.toml: Encountered invalid utf-8 sequence

**卡上的 cod6.toml 被写坏了** → 整份配置失效 → `gpu_plugin` 为空 → SDK 不加载 GPU 插件
→ 没有 Vulkan、没有 GPU Commands 线程 → guest 空转 → 零帧。

对比 154/155（toml 解析 0 失败，正常）与 156~159（各 1 次失败，全黑屏），完全对应。

**修复**：重拷 toml + 代码里加兜底（`gpu_plugin` 为空就用 `xenos` 并打警告）。
**副作用**：那几次黑屏运行时 `user` 目录被当成新档写入，**存档丢了** —— 这是代价，记下来。

## 160 号 · 恢复正常（v63）

```text
Vulkan instance API version 1.4.354
14.4~16.0 fps，invitado 505/883 MB，toml 解析失败 0 次
[cod6] DIAG63: pipeline propia=OK  formato_swapchain=44(B8G8R8A8)
```

**我们自己的管线在真机上创建成功**。这是第一次拿到这个确定答案。

## 161~162 号 · 画了但看不见（v64/v65）

- 161：`NATIVO PIPELINE: vs=0 ps=0 layout=0 pipeline=0`（全成功）、`DIAG64` 只打印一次
  → 说明每条帧都在发绘制，**但帧率没变化** → 绘制被丢弃。
- 162：怀疑格式（swapchain 是 **37**，我们按 44 建）→ 两种格式各建一条管线都画一次
  → 仍然没像素、帧率仍不变。
- 结论：**问题不在格式，在"没有活动的渲染目标"**。`IssueSwap` 里根本没有正在渲染的 pass。

## 163 号 · 转折点：在 presenter 里画（v66）

换了个完全不同的注入点：presenter 的 swapchain render pass 里、最终 blit 之后，
用一个**不需要管线**的 `vkCmdClearAttachments` 画 600×360 洋红矩形。

结果：**屏幕上真的出现了洋红矩形**（用户发了照片），`DIAG66` 执行，15.7~16.1 fps 正常。

**这一轮确定了渲染器的落点。**

## 164 号 · netloader 又坑了一次

推 v67 后黑屏，而且卡上的日志**一个字都没新增**；从卡上下的 nro md5 和我推的**对不上**。

结论：**netloader 上传不可靠**（每次输出都停在 34.42% 那行，没有完整性校验）。
从此 nro 一律线缆复制。

## 165 号 · 线缆验证（v68）

线缆拷 v68 → 正常跑起来（`VERSION 2026-10-31-68`、16 fps、888 MB）
→ 确认上一轮的黑屏是**传输问题**，不是代码。

## 166 号 · 里程碑② 完成（v69）

把"clear 矩形"换成**用我们自己管线 + 我们自己着色器画的三角形**，管线按
`paint_context_.swapchain_render_pass` 创建、格式用 `swapchain_render_pass_format`。

结果：**整屏被我们画的三角形覆盖**（用户："屏幕红了！"），16 fps，零 Vulkan 错误。

**从这一刻起，我们拥有了一条能往屏幕上画任意几何体的通路。**

## 这一段学到的三条规矩

1. **配置坏了比代码坏了更常见**：先看 `Failed to parse config`，再看代码。
2. **没有活动渲染目标时，画什么都不会报错**：帧率不变就是最响的信号。
3. **传输不可靠**：nro 一律线缆 + md5 核对；日志走 HTTP 自己拉，不依赖人搬。
