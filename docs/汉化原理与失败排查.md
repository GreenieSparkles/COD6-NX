## 一、COD 的本地化是怎么存在游戏里的

IW 引擎的游戏文本不是外部文本文件，而是**烤进 FastFile（`.ff`）里的资产**。一次汉化涉及三层，缺一层就失败：

| 层 | 存在哪里 | 内容 |
|---|---|---|
| **① 字符串表** | `.ff` 内的 localized string 资产 | 每条 UI 文本 / 字幕 / 提示的文本 |
| **② 字体图集** | `.ff` 内的 font 资产（image） | 字形贴图（位图），每个字符对应的 UV 区域 |
| **③ 码页 / 编码** | 字符串资产的编码约定 | 单字节 / 双字节，或 UTF-8 |

**关键点：中文的字符集太大，拉丁字体图集里没有汉字字形。** 所以汉化**必须同时替换字体图集**，只换字符串一定显示为方块或空白。

## 二、COD6 中文版与英文版的实测差异 ✅

用同一份游戏的两种发行版对比（文件大小，字节）：

| 文件 | 中文版 | 英文版 | 差异含义 |
|---|---|---|---|
| `code_post_gfx.ff` | **1,217,036** | **2,091,894** | **字体/UI 资产，中文版小 42%** |
| `code_post_gfx_mp.ff` | 1,122,341 | 1,980,588 | 同上（多人） |
| `common.ff` | 37,866,074 | 38,295,849 | 差 1.1%（音轨/语言资源） |
| `af_caves.ff` 等关卡 | 各小 2~4% | — | 删掉了非中文语音 |
| `patch.ff` | **不存在** | 存在 | 中文版没有这个补丁包 |
| `default.xex` | **5,033,984** | 5,029,888 | **不同编译**（差 4096 字节） |

**结论 ✅**：
1. 中文版是**独立的发行版**，不是"英文版 + 补丁"；
2. `code_post_gfx.ff` 就是字体/UI 包，中文版换成了含汉字的版本；
3. `default.xex` 也不同 → 两者**不是同一个可执行文件**，不能混用资源。

> 这意味着：**中文版和英文版的 `.ff` 不能互换**。用英文的 `.xex` 配中文的 `.ff`，或反之，都可能读不到字体资产。

## 三、汉化失败的六种具体原理

### 3.1 只换字符串，没换字体 —— 显示方块 □□□

字体图集里没有汉字字形，游戏把每个汉字映射到"缺字"图块。

**判定**：文本长度对（占位大小合理），但全是方块。
**修法**：必须同时替换 font 资产（图集 + 字形表）。

### 3.2 换了字体，但资产索引没更新 —— 空白 / 崩溃

`.ff` 是打包格式，内部有**资产偏移表**。手工替换图片而不改偏移/大小，游戏按旧偏移读 → 读到别的资产或越界。

**判定**：界面某块全空，或进菜单就崩。
**修法**：用工具的完整替换流程（保持偏移表一致），不能直接二进制覆盖。

### 3.3 端口读错了 `.ff` —— 显示原语言

移植端口如果**写死了资源路径或语言**（例如只认 `code_post_gfx.ff` 的英文版），你放中文版进去也不会被读。

**判定**：完全显示原语言，一个汉字都没有。
**修法**：查端口的资源加载路径与语言 dvar（见第五节）。

### 3.4 字体贴图的**格式**走了错的路径 —— 字形乱、糊、花

字体图集常见格式：`A8`（单通道）、`DXT5`（BC3）、`8_8_8_8`。
如果端口的纹理路径对某种格式处理有偏差，**只有字体坏**（因为字体用的格式和别的贴图不同），表现为：字形发花、笔画断裂、字符位置错位。

**判定**：不是方块也不是空白，而是**字形本身渲染错误**。
**关联**：本项目正在查的贴图崩坏问题就属于这一类——**如果连拉丁文本都显示发花，那就是纹理路径的问题，不是汉化的问题**。

### 3.5 码页不匹配 —— 乱码

字符串按单字节存（拉丁），实际塞进 UTF-8 双字节 → 显示成 `Ã¤Â¸Â` 之类。
**判定**：一堆奇怪符号、长度翻倍。
**修法**：字符串必须用资产声明的编码写入。

### 3.6 字距 / 行距表没改 —— 文字重叠或截断

字体资产里带**每个字符的宽度、字距、行高**。中文是全角，若沿用拉丁的宽度表：字符挤在一起、或每行只显示一两个字。

**判定**：能认字，但排版错乱。
**修法**：字体资产的字形表（glyph metrics）必须配套。

## 五、排查流程（按顺序做，每步都有判据）

### 第 0 步：确认游戏本身是不是中文版

```bash
# 看 game_root 里这些文件的大小
ls -l game_root/code_post_gfx.ff game_root/common.ff game_root/default.xex
```

- `code_post_gfx.ff` ≈ **1.2 MB** → 中文版 ✅
- ≈ **2.1 MB** → 英文版 ❌

### 第 1 步：确认端口读到的是哪个目录

看端口日志里的 `paths: game=...` 一行，确认 game_root 指向的是中文版目录，**不是那份英文的**。

### 第 2 步：确认语言设置

IW 引擎有语言相关的 dvar（各版本名字可能不同），常见：`loc_language`、`sys_language`。
查游戏内是否被强制成其他语言；端口若提供 `*_dvar_set` 之类的入口，可以先试着不动它（默认应跟随 `.ff` 的内容）。

### 第 3 步：区分"文字没换"和"字形坏了"

| 现象 | 层级 | 下一步 |
|---|---|---|
| 全方块 □□□ | 字体图集缺字形 | 换 font 资产（3.1） |
| 全空白 | 资产偏移错 | 重新打包 `.ff`（3.2） |
| 显示原语言 | 读错数据/写死语言 | 查路径与 dvar（3.3） |
| **字能认出但发花** | **纹理路径问题** | **不是汉化问题**，去查渲染（3.4） |
| 乱码 `Ã¤Â¸Â` | 编码不匹配 | 按资产编码写入（3.5） |
| 字挤在一起/截断 | 字形宽度表 | 换配套 glyph metrics（3.6） |

### 第 4 步：确认字体贴图的格式

本项目可以导出运行时的贴图（`cod6_debug_capture_every` + `cod6_debug_tex_album`）。
字体图集通常在 1024×1024 或 512×512，格式多为 `8`（A8）或 `DXT4_5`。
**导出后解码**：如果拉丁字母和方块都发花 → 纹理路径问题；如果只有汉字位置空 → 字体资产问题。

## 六、要把一份汉化做进移植，需要什么（清单）

| # | 需要的东西 | 现状 |
|---|---|---|
| 1 | 中文版的原版游戏文件（`.ff` + `.xex`） | ✅ 有（COD6 中文 ISO） |
| 2 | **`.ff` 解包/重打包工具** | ❌ **我们没有**（这是硬门槛） |
| 3 | 字体图集与字形表（glyph metrics） | ❌ 需从中文版 `.ff` 里取 |
| 4 | 字符串表（localized strings） | ❌ 同上 |
| 5 | 端口能正确渲染字体用的纹理格式 | ⚠️ 与我们正在修的贴图问题同一件事 |

**最大的现实门槛是第 2 项**：没有 `.ff` 打包器，就只能**整体用中文版数据**，不能做"英文版 + 中文补丁"这种混搭。

好消息是 **COD6 中文版是完整发行版**，所以我们的路线是"直接用中文版数据"，绕过了这个门槛。

## 七、参考案例

### 7.1 WAW 移植（Lizarddav，2026.11.01）

- 发布包只带 **俄语 README**，游戏本身是英文战役
- 有 `codwaw_dksh.pak`（deko3d 着色器）+ `codwaw_shaders.nfsp`（Vulkan 着色器）**两个后端**
- **没有**中文资源，也没有汉化层 → 用它做中文只能靠替换 `.ff`

### 7.2 COD4 中文汉化版（B站 UID 122607497 整理）

- 基于 Lizarddav 的 COD4 移植（README_RU 第 1 行 `От Lizarddav.`）
- 中文是**替换游戏资源**实现的（不是端口层）
- 附带配置生成器、成就检测器等工具

### 7.3 本项目 COD6

- 直接用**官方中文版数据**，端口层不做任何汉化处理
- 所以"汉化"这件事在我们这里是**零工作量**，只要纹理路径正确
